# REALITY 域名检测与 ASN 解释

部署前从实际 VPS 检测用户提供的 REALITY 域名。该域名是被伪装的真实 TLS 站点；
XHTTP 域名则属于用户并指向 CF 橙云，按 [CF 清单](cloudflare-checklist.md) 单独检查。

ASN 是自治系统编号，表示由某个组织管理并公布路由策略的网络。它不是 IP 地址、国家代码或
机房编号。同一公司可以拥有多个 ASN；一个 ASN 也可以横跨多个国家。地理国家来自位置资料，
ASN 来自 BGP 路由归属，两者不要互相推断。

| 检查 | 判定与处理 |
|---|---|
| R01/R02 DNS 与 TCP 443 | 解析或连接失败则不可部署；当前传输检查要求 IPv4，不宣称纯 IPv6 已支持 |
| R03/R04 TLS 1.3 与 ALPN h2 | 必须有通过证书校验的 TLS 1.3 握手和 h2 协商 |
| R05 混合密钥交换 | 检查 X25519MLKEM768；目标或本地探针不支持时 WARN，允许既定 X25519 回退 |
| R06 证书 | 域名、信任链校验通过，剩余有效期超过 7 天 |
| R07 HTTP | HEAD 2xx 通过；裸域到自身 www 的跳转 WARN 并复查最终域名，其他跳转或不可用响应需处理 |
| R08/R09 目标筛选 | 遵守现有排除规则；热门目标提示仅为参考，不声称列表完整 |
| R10 ASN | 输出源站/目标 AS 编号，分别统计匹配、不同、查不到；不同 ASN 不是协议不兼容 |
| R11/R12 延迟与稳定性 | 五次探测，中位 TLS 延迟超过 300ms、证书/ALPN 波动或探测不足时 WARN |
| R13 ML-DSA 条件 | 证书链 DER 总长超过 3500 字节只表示大小前提满足；未满足用 mldsa off |

ASN 相同只说明观测到的公网路由归属有交集，不能保证伪装效果、网络距离或抗封锁能力。
ASN 不同的站点仍可能是合格目标。优先考虑协议和证书正确、从 VPS 连接稳定、延迟合适，
不能为了“同 ASN”放宽 TLS 校验。解析回源站自身会导致回环，必须拒绝。

报告时用简明中文说明总体可用性、硬性失败项和每个 WARN；ASN 举例：
“源站 ASxxxx，伪装站 ASyyyy，不相同；这是选站参考，不影响已通过的 TLS 检查。”
查询不到就说未确认，不给 PASS。无需展示证书全文、原始日志或节点配置。

DNS/CDN 答案可能随时间和地理位置变化。ASN 检查包含 A/AAAA 快照、去重后最多 8 个 IP，
传输探针由系统解析器选择连接地址，不是每个解析 IP 都通过了 TLS 实测。
公网 IP 会发送给 RIPEstat 查询服务，每次查询设超时；ASN 无法查询不会掩盖 TLS 硬性失败。
网站 HEAD 拒绝也可能是反爬策略，需针对实际失败排查，不直接声称站点彻底不支持 REALITY。

检测通过后仍须按 [实际代理验收](verify-and-diagnose.md) 验证生成的 A/B 节点。
域名探测通过不等于最终客户端已连通，也不保证长期可用。
